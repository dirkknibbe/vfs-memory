## What this project is

A hardened, agent-agnostic file-system-as-memory for LLM agents. Per-project `.vfs/` directory (like `.git`). CLI usable from any agent that can shell out — Claude Code, Codex, Copilot, Cursor. Stdlib-only Python 3.9+. Threat model: prompt-injected agent, malicious local non-root process, supply chain. Co-resident same-UID peers are treated as the normal case (locking + CAS).

## Key facts to know if you're resuming cold

- **Names:** Repo `vfs-memory`, PyPI `agent-vfs`, import `agent_vfs`, binary `vfs`. The CLI's `.vfs/` directory uses the `vfs` short form (it's a user-facing path).
- **No `tempfile.mkstemp`** in `agent_vfs/backends/localfs.py` — can't accept `dir_fd`. Atomic writes use `os.open` with `O_CREAT|O_EXCL|O_NOFOLLOW` and `dir_fd=parent_fd`, then `os.link` for CAS-create (atomic-refuse-if-exists), `os.rename` for overwrite/update.
- **No `os.umask` in concurrent-write code paths** — `os.umask` is process-global, threads leak state. Use `os.fchmod` after open instead. The CAS-create + diag-log path do this; if you add a new write path, do it the same way.
- **No `Co-Authored-By: Claude` trailer on commits.** User's global rule; reason: full responsibility for the code. Applies to all repos.
- **No `$VFS_PROJECT_ROOT` env var.** It was removed during the 4-agent review as a cross-project bypass for prompt-injected agents. Cross-project access is `--root /abs/path --as-user` (TTY-gated) or `VFS(root=...)` library only.
- **`vfs migrate` is TTY-gated.** No env override. Walks legacy `~/.claude/projects/<slug>/memory/` with symlink containment.
- **AST-based static checks** in `scripts/static_checks.py` — not grep. Catches `import socket`, `import subprocess`, etc. A separate substring scan rejects shell-call and dynamic-code-evaluation builtins; the patterns are constructed at runtime in the script so it doesn't trip its own scan.
- **Hand-rolled TOML reader** in `agent_vfs/config.py` — `tomllib` is 3.11+, `tomli` would break stdlib-only on 3.9/3.10.
